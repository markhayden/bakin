# Implementation Plan: Zero-Install Image Processing (#889)

Spec: `.claude/specs/media-zero-install-889.md` (approved 2026-09-20)

## Overview

Give compiled-binary installs working sharp by default: a shared
download-verify-commit primitive (debt payoff: 3 hand-rolled copies → 1),
a pinned npm-tarball store installer with in-binary `Bun.build` bundling
(spike-proven), a disk-fallback leg in the ONE sharp loader, onboarding
component #16, a loud `media.sharp` doctor check with one-click repair,
remediation-aware error messages, and a compile-and-run regression pin.

## Architecture Decisions (from spec interview)

- Install-time only; no network in request paths.
- npm registry tarballs, sha256-pinned: 4 platform-neutral (`sharp`,
  `@img/colour`, `detect-libc`, `semver`) + 2 per platform (`@img/sharp-<p>`,
  `@img/sharp-libvips-<p>`) × {darwin-arm64, linux-x64, linux-arm64} = 10 pin
  entries, generated by script.
- Store: `~/.bakin/media/sharp/<version>/` — staging → probe-resize verify →
  atomic rename; receipt file is the loader's trigger.
- Shared primitive is streaming + file-based (model files are too big for
  in-memory), small composable functions, not one mega-function.
- Loader order: bundled `import('sharp')` → store bundle; cached failure
  re-probes when a receipt appears (doctor repair works without restart).
- `sharp` joins the compile externals (#837 posture).

## Dependency Graph

```
T1 shared downloader ──┬─→ T2 refit bin-installer        (parallel)
                       ├─→ T3 refit requirements-installer (parallel)
                       └─→ T5 media store installer
T4 pin + regen script ──→ T5 ──┬─→ T6 loader fallback + externals
                               └─→ T7 compile-and-run regression
T6 ──→ T8 onboarding component ──→ T9 doctor check + repair
T6 ──→ T10 error messages
T9/T10 ──→ T11 docs + follow-up issue
```

High-risk first: the compiled-binary mechanics were de-risked by the spike;
remaining highest risk is the two refits touching live install paths — they
sit early (T2/T3) so regressions surface before the feature work stacks on top.

## Commit Strategy (rollback checkpoints)

Branch `feat/889-media-zero-install` in the MAIN checkout (3737 serves it for
live testing). One commit per task, each green (lint + typecheck + touched
suites) — every commit is a revert point:

| # | Commit | Rollback semantics |
|---|---|---|
| C1 | `feat(core): add shared download-verify-commit primitive` | pure addition — revert freely |
| C2 | `refactor(packages): refit bin-installer onto shared downloader` | independently revertible |
| C3 | `refactor(core): refit requirements-installer onto shared downloader` | independently revertible |
| C4 | `feat(media): pin sharp prebuild set + regeneration script` | pure addition |
| C5 | `feat(media): store installer with in-binary bundling + probe verify` | revert C5–C10 = feature off, refits keep |
| C6 | `feat(media): loader store fallback + compile-time sharp external` | with C5 |
| C7 | `test(media): compile-and-run regression + embed-premise teeth` | pure addition |
| C8 | `feat(onboarding): media component (order, version, allowlists, repair whitelist)` | revert restores 15-component surface |
| C9 | `feat(health): media.sharp check with one-click repair` | independently revertible |
| C10 | `fix(media): name the remediation in sharp-missing errors` | independently revertible |
| C11 | `docs(media): media-pipeline knowledge doc + stale-doc sweep` | pure addition |

No force-pushes after Mark starts live-testing; fixups land as new commits.

## Risks and Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Refits regress live install paths | High | T2/T3 zero-test-edit rule; isolated commits; done first |
| `Bun.build` behaves differently inside the real compiled binary vs spike fixture | High | T7 runs the REAL installer code compiled; Checkpoint B gates on it |
| Linux RUNPATH placement differs from darwin rpath | Med | placement map per platform; linux CI leg at Checkpoint B before Phase 3 |
| Future sharp bump changes native candidate paths | Med | install-time probe verify fails staging, never commits; runbook pins the ladder |
| npm registry down during onboarding | Low | honest failed component; doctor repair retries later |
| Stale `getBakinPaths` test mocks lacking `media` | Med | loader/installer guard missing key; CLAUDE.md testing note |
| Wrong dep versions in pin (hoisted-semver spike bug) | Med | regen script resolves from sharp's own npm metadata; probe verify backstops |
