### Redesign opportunities

- 45 byte-identical TUI wrapper functions (verified: 45 hits of `renderToString(createElement` between lines 205-624 and 2156-2217). Every one is the same Promise.all([import(ui-module), import(render-to-string), import('react')]) + console.log pattern, ~10 lines each (~480 lines total). Replace with one generic `renderInkReport(load: () => Promise<Component>, props)` helper (~15 lines) that preserves the lazy loading. This alone removes ~450 lines and is the prerequisite for clean seams.
- BINARY_ONLY_COMMANDS is a permanently empty Set (line 3789: `const BINARY_ONLY_COMMANDS = new Set<string>()`) threaded through printHelpTui (238), USAGE (3790), and the default branch (4567). Dead abstraction — delete it and the excludeNames plumbing, or move the real binary-command list here.
- Module-load side effect: `const USAGE = renderCliUsage(...)` (3790) executes registry rendering every time the module is imported — including every binary delegation through src/core/cli.ts:250 even for commands that never print usage. Make it lazy.
- Five hand-rolled flag parsers for the same patterns: --slow-ms in two forms (876-895), --lines in two forms (3157-3169), --table/--limit/--facets duplicated between reindex (4478-4482) and search (4494-4503), inline flagValue() closure for plugins publish (4282-4285), parseAgentsFlags (1793-1838). src/core/cli/options.ts and parser.ts already exist — consolidate on one flag-parsing helper during the split.
- Every command duplicates the TTY/plain/JSON branching inline (`if (process.stdout.isTTY) {...tui...; return} print(result)`) — e.g. cmdSetupService's darwin success block (2809-2830) and linux success block (2868-2889) are near-identical 20-line copies differing only in the service label. Introduce a single `emit({tui, plain, json})` output dispatcher; most cmd functions shrink by half.
- Boundary inconsistency: the file header claims 'All commands are thin wrappers around the Bakin HTTP API' (line 4), and cmdSettingsGet/Set go through /api/settings (803, 857), but cmdDiagnosticsStartup writes settings locally via getSettings/updateSettings (static import line 20; 917-930), and runOfflineDoctor / onboarding commands import server-side core modules directly. Decide per-module which side of the HTTP boundary each command lives on and group accordingly (system.ts = HTTP; onboarding.ts/doctor offline = local-core, explicitly).
- cmdPluginsRestore bypasses the api helpers with a raw fetch (1441-1451) to get non-throwing status handling that apiPostJson (147-158) already provides — unify on apiPostJson.
- Three copies of the same readline y/N prompt: confirmPrompt (2219-2229), confirmDoctorRepair (2231-2241), confirmDoctorDelegate (2243-2253); the latter two are confirmPrompt with an interpolated message and a missing isTTY guard. Collapse to one, and note src/core/cli/consent-prompt.ts already owns a richer prompt.

### Shared-extraction candidates

- src/cli/schedule.ts re-implements apiGet/apiPost/apiDelete + BASE_URL (schedule.ts lines 7-46) — and the copy has drifted: bakin.ts honors `process.env.BAKIN_URL` (bakin.ts:53) while schedule.ts:7 only reads PORT, so `BAKIN_URL=... bakin schedule list` silently hits the wrong host. The proposed src/cli/http.ts fixes a real bug, not just duplication.
- The lazy ink-render pattern (Promise.all import of ui component + render-to-string + react, then renderToString(createElement(...))) is the de-facto rendering contract for all CLI TUI output; the generic helper belongs in src/core/cli/ui/ (next to render-to-string.ts) so schedule.ts, src/core/cli.ts, and future command modules share it instead of re-pasting.
- isServerConnectionError (140-145) classifies transport failures by error-message text ('ECONNREFUSED', 'fetch failed'); a typed connection-error from the shared HTTP client in src/core/cli/ would align with the repo rule of classifying errors by kind, never message text.
- doctorRepairRecord/doctorRepairRequestList (2358-2373) and jsonObject/parseJsonText (114-127) are the same safe-JSON-shape guards written twice in one file; they belong next to extractApiErrorMessage in src/core/cli/api-error.ts or a small src/core/cli/json.ts.

### Risk notes

Entry path is load-bearing three ways: package.json bin maps "bakin" -> ./cli/bakin.ts (package.json:10), the compiled binary's dispatcher dynamic-imports '../../cli/bakin' and destructures { main } (src/core/cli.ts:250), and scripts/instance.ts:155,208 + scripts/instance/sandbox.ts:35 shell out to `bun run cli/bakin.ts` — so cli/bakin.ts must survive as a file exporting main() with the import.meta.main guard (4630-4632). The binary delegation contract is fragile: delegateToSourceCli monkey-patches process.exit to throw DelegatedCliExit (src/core/cli.ts:243-247) and main() deliberately rethrows BakinDelegatedCliExit and /^exit:\d+$/ errors (bakin.ts:4588-4593); extracted command modules MUST keep calling process.exit (not return codes) or the binary's exit-code plumbing and tests like doctor-repair.test.ts (`rejects.toThrow('exit:1')`, line 120) break. All heavy deps (react, ink, src/core/cli/ui/*, onboarding components, whiskit build) are dynamically imported on purpose to keep binary startup cheap (comment 55-57) — the split must not let any new module statically import them into the entry's import graph; conversely the static imports at the top (whiskit publish/artifacts-index lines 8-15, settings line 20, import-export 23-29) already load server-side core on every CLI invocation and should move into their command modules as part of the split. Mutual lazy dependency exists between cli/bakin.ts and src/core/cli.ts (bakin.ts 2698-2699 and 4458 import src/core/cli; src/core/cli.ts:250 imports bakin) — both sides must stay dynamic or the split creates a static cycle. Module-load side effects to preserve/contain: BASE_URL env read (53), lazy __cliAgent cache (58-65), and the eager USAGE = renderCliUsage(...) (3790). Tests in tests/cli/* mock dependency modules (onboarding components, ui modules, settings) by their own resolved paths and then import { main } — they survive the split as long as the extracted code keeps importing the exact same modules; only relative specifiers change. No registerPlugin/addExecTool/globalThis-HMR state anywhere in this file (verified). One behavioral landmine: cmdLogs ends with `await new Promise(() => {})` and a SIGINT handler (3326-3332) — whatever module owns it inherits a never-resolving promise that would hang any caller that awaits it outside the process-exit flow.

### Redesign opportunities

- Capability groups are object-literal instance properties closing over `this` (agents at runtime.ts:342, channels at 533, skills at 736, cron at 992, images at 866) but most only need `this.exec`, `this.logger`, and a gateway accessor. Redesign as factory functions taking a narrow ctx ({ exec, execCron, logger, approvalGateway() }) so each seam module is independently testable and the class becomes a composition root.
- Config read/write split across files: packages/adapter-openclaw/src/config.ts owns readOpenClawConfig + the cache + resetOpenClawConfigCache (config.ts:38, 92), but writeOpenClawConfig lives in runtime.ts:1528-1532 and manually invalidates that cache. Move all config mutation (writeOpenClawConfig, upsertOpenClawAgentConfig at 1545, updateOpenClawAgentIdentity at 1586, updateAgentAllowlist at 1598, removeOpenClawAgentConfig at 1609) into config.ts so cache + invalidation co-locate.
- Within-file copy-paste: normalizeToolList (runtime.ts:1430-1441) and normalizeCronToolsAllow (2075-2087) are the same dedupe-trim function; three JSON path walkers getJsonPath (1471), stringAtPath (1720), readPath (2306); isRecord (1886) and isPlainObject (2302) are identical with two names used inconsistently throughout; truncate (1880) vs truncateMiddle (2746) overlap. Unify in json-utils.ts during the split.
- errors.ts declares itself 'The ONE place OpenClaw provider error strings are interpreted' (errors.ts:2-7), yet runtime.ts string-matches provider output in isPluginAllowlistOpenFailure (runtime.ts:183-195, matches 'plugins.allow is empty') and isExpectedNativeApprovalResolveMiss (1876-1878, regex /expired|not found|unknown/). Move these into errors.ts to honor its charter.
- DEFAULT_SETTINGS (runtime.ts:70-74) calls findOpenClawBinary() at module load — an eager PATH scan with accessSync per candidate on every import, and redundant since mergeSettings (1480-1490) re-resolves via resolveOpenClawBinary anyway. Make binary resolution fully lazy when extracting cli.ts.
- Type-only import cycle: runtime.ts:47 imports OpenClawRuntimeAdapterOptions from './index' while index.ts:2 imports OpenClawRuntimeAdapter from './runtime'. Harmless today but a trap during the split — move the options type into the adapter module (or a types.ts).
- Bakin product knowledge hardcoded in adapter presentation: summarizeToolNamePurpose (runtime.ts:2687-2694) maps bakin_exec_projects_*/bakin_exec_messaging_* tool names to labels, and summarizeShellCommandPurpose (2656-2675) knows mcporter/gh/bx idioms. These labels rot silently as plugins change; isolating them in activity-labels.ts makes the maintenance surface explicit (data-driven map would be better).
- Fabricated identifiers from Date.now(): messaging.send returns id `msg-${Date.now()}` (runtime.ts:510) and cron.runNow falls back to `run-${Date.now()}` (1003) — collision-prone under concurrent dispatch; use randomUUID (already imported at line 5).

### Shared-extraction candidates

- deepMerge exists twice with same semantics: runtime.ts:2291-2300 and packages/core/src/settings.ts:381 — extract one into packages/core (adapter already imports @bakin/core/media at runtime.ts:33, so the dependency direction is established).
- isRecord/isPlainObject type guard has at least 8 private copies: runtime.ts:1886 + 2302, trajectory-forensics.ts:55, gateway-rpc.ts:385, approval-gateway.ts:119 (all in this package), plus packages/core/src/settings.ts:312, packages/core/src/plugins/signatures.ts:23, packages/core/src/plugins/manifest.ts:42, src/core/plugins/import-export.ts:47, src/core/cli/api-error.ts:1 — one packages/core type-guard util ends the proliferation.

- parseJsonValue/parseJsonObject lenient-parse pair (runtime.ts:2924-2937) — generic 'parse or null' helpers; gateway-rpc.ts and trajectory-forensics.ts parse JSON defensively too and could share them at minimum at the package level (json-utils.ts seam), plausibly in packages/core.

### Risk notes

Low overall: runtime.ts's real public surface is tiny — index.ts:2 imports only the OpenClawRuntimeAdapter class, and consumers (src/core/runtime-adapter-factory.ts:2, dev/imitation-crab/harness.ts:8, all runtime-*.test.ts files) go through createOpenClawRuntimeAdapter. Two test files import internals directly and will break unless paths are updated or re-exports kept: tests/adapter-openclaw/merge-chat-streams.test.ts:16 (mergeChatStreams) and tests/adapter-openclaw/session-store-cache.test.ts:26-30 (SESSION_STORE_CACHE_MAX + three __*ForTest hooks). Module-scope mutable state moves with the split: the sessionStoreCache LRU Map (runtime.ts:2456) and the approval-response dedupe ring (instance state, 272-273) — keep the cache and its test hooks in one module (session-activity.ts) so cache identity stays singular. DEFAULT_SETTINGS (line 70) performs a PATH scan + accessSync at module load; wherever cli.ts lands, that side effect moves with it (or gets fixed per the redesign note). No registerPlugin/addExecTool/globalThis-HMR side effects exist in this file — it is pure server-side adapter code compiled into the binary via the static factory import; no embedded-asset or vendor-bundle implications. One type-only cycle (runtime.ts:47 <-> index.ts:2) must be broken during the split. The architecture test tests/architecture/adapter-boundary.test.ts enforces that raw OpenClaw home/path access stays inside packages/adapter-openclaw — all proposed seams are package-internal siblings so they pass, but the shared-extraction candidates must take only pure helpers (deepMerge, isRecord, redaction) to packages/core, never anything calling getOpenClawHome/getOpenClawPath. Tests rely on filesystem fixtures + a recorded fake binary (runtime-channels.test.ts passes settings.binaryPath), so behavior-preserving extraction keeps the suite green; run bun test tests/adapter-openclaw --isolate after each seam.
