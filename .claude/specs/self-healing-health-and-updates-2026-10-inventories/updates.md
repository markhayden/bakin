## B. Package source — the broken-manifest case
- `installedPackages()` parses with strict zod `parseManifest`; failure → `manifestError` (package-wiring.ts:111-122). `observe` returns blocked "manifest unreadable — reinstall" + manual sync pointer (package.ts:131) BEFORE ls-remote → never learns whether upstream fixed it.
- `packages sync` cannot repair in place: `updatePackageById` no-ops when `fetched.commitSha === entry.commitSha` (updater.ts:88-101); `applyLocalProjection` re-parses the broken installed manifest and throws (sync.ts:213-227). Works only when upstream moved to a commit with a valid manifest (the updater parses the STAGED manifest, updater.ts:105, and unprojects from lock projections, so the old manifest is not needed).
- Fix: (1) observe remote even with manifestError — moved → `update-available` reason `repair`/`newer-commit` with `operation` action; not moved → blocked "upstream still ships this manifest". (2) `case 'package'` in apply.ts:291 with a `packageSyncOperation(key|agentId, origin, expected)` exported from packages/dynamic.ts:117-145 and agent-packages/dynamic.ts:215-245 (packs `syncPack(key)`, agents `syncAgent(agentId)`; record id `package:<id>` vs lock key `id@ver` which stays the OLD version after update, updater.ts:223). (3) `expected {sha}` on `UpdateOptions` so the updater refuses a commit other than the reviewed one, plus force/reinstall to skip the same-sha no-op. (4) consent: pack requirement bins install WITHOUT a consent token (updater.ts:148-158); agent sync may return `migrationRequired`.
- `1.0.0 → 1.0.0 (ced0bb6)` is manual only because package.ts:129 hardcodes manual; header comment (:10-11) "until that path is an operation" is stale — sync routes are operations since #895 (packages/dynamic.ts:117-145).

## C. Plugin upgrade end to end
- CLI `plugins upgrade <id>` (plugins.ts:415-460): POST `/api/plugins/upgrade {pluginId}`, follows preview op; `awaitingConsent` → `promptUpgradeConsent`; `ready` → commits silently `{accepted:true, consentToken}`; ≤3 rounds.
- REST (packages/host/src/api/plugins/upgrade.ts): post :63, `pluginUpgradeOperation` :109. Preview kind `fetch` holds nothing; commit kind `upgrade` holds install-state, verifies token (:127-144), `upgradePlugin`, activates (:160-174). Fingerprint hashes token + expected (:57-61,120).
- Health→Updates: `confirmApply` → `deps.pluginUpgrade(id,{accepted:!!consentToken, consentToken, expected})` (apply.ts:294); UI consent dialog (updates-tab.tsx:246-255; use-updates.ts:238-260); CLI `updates apply` same loop (updates.ts:271-288).
- Consent token (consent-token.ts:43-53): `{source:'upgrade:<id>', manifestSha, permissions[], bins[{name,version,sha256,member?,sizeBytes?}], expiresAt}` HMAC, 5-min TTL — FULL declaration, not a diff. `expected {version,sha,digest}` binds the target.
- `upgradePlugin` (src/core/plugins/upgrade.ts:66-128): refuses core + linked; artifact → `upgradeArtifact` (`newestCompatibleVersion` + `artifactUpgradeTarget`, upgrade-artifact.ts:79,113); else GitHub subpath staging clone / fast-forward / local re-copy.
- `newestCompatibleVersion` (compatible-version.ts:41-50): highest semver whose platform/neutral build `artifactRunsOn` (contract + bakinRange). `artifactUpgradeTarget` (:57-61): stranded → any compatible (even same-version rebuild); running → forward only.
- Stranded: `health.plugin-artifacts` → incident + `upgrade-plugin-artifact` repair (plugin-artifacts.ts:63-79,118-142,238-330): safety `manual` (approval), plan previews each plugin (version, sha, digest, permissions, bins), apply re-previews, refuses drift, commits with `preview.consent` + expected. "all actionable" bundles every stranded plugin.
- "Everything at once": only that repair (stranded only), `bakin agents sync` no-id (agents.ts:557-561), team/global sync (teams.ts:207). Policy in updates.md:530: "No auto-update, no Update all".
