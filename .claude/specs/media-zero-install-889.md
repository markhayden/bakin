# Spec: Zero-Install Image Processing for Compiled Binaries (#889)

Issue: https://github.com/markhayden/bakin/issues/889
Status: DRAFT — pending approval
Spike: full chain proven 2026-09-20 in a compiled fixture (in-binary `Bun.build`
bundle of sharp's JS from a disk store → native `.node` via sharp's relative
candidate + libvips rpath → disk import → real metadata/resize/JPEG encode).

## Objective

Compiled-binary installs get working image processing (downscale, thumbnails,
dimensions, exports) **by default, with no manual step**. Today `bun build
--compile` cannot embed sharp's native prebuilds, so every binary install
silently runs without image support: >2 MB enrichment fails unrecoverably,
asset exports throw, thumbnails degrade to ffmpeg-or-nothing, and the
`assets_visual` search leg loses thumbs.

Success looks like: fresh binary install → onboarding provisions media →
generate a >2 MB image → enrichment succeeds, zero user action. Existing
installs see a loud doctor incident with a one-click repair.

## Decisions (interview log, 2026-09-20)

| Branch | Decision |
|---|---|
| Mechanism | Pinned prebuild download (antfly/capability-pack house pattern) — NOT wasm fallback, NOT embed-spike |
| Trigger | Install-time only: onboarding component + `bakin install media` + doctor one-click repair. NO lazy self-heal in request paths |
| Artifact | npm registry tarballs (immutable), 6 per platform, each sha256-pinned in a committed pin file |
| Platforms | `darwin-arm64`, `linux-x64`, `linux-arm64` (glibc) — exactly the binary release matrix; musl et al report unsupported-platform |
| Downloader | Extract ONE shared download-verify-commit primitive into `packages/core`; media installer + `bin-installer` + `requirements-installer` refit onto it. Antfly installer: follow-up issue only |
| Doctor | `media.sharp` — unclassified (never demotes), action_required disposition when a compiled install lacks working sharp, one-click repair. OK in dev tree via bundled import |
| Docs | New `.claude/knowledge/media-pipeline.md` + stale-doc updates (binary-size.md, CLAUDE.md, doctor inventory, Astro install docs if present) |

## Mechanism (proven by spike)

Compiled bun binaries CAN import plain JS files from absolute disk paths and
CAN `require()` a `.node` by absolute/relative path (dlopen + rpath work).
They CANNOT resolve bare specifiers (`require('detect-libc')`) against a disk
`node_modules`. Therefore:

**Install** (`bakin install media`, idempotent, verify-then-commit):
1. Resolve platform key; unsupported → honest failure naming the platform.
2. Download the 6 pinned tarballs from registry.npmjs.org (sha256 each):
   `sharp`, `@img/colour`, `detect-libc`, `semver`,
   `@img/sharp-<platform>`, `@img/sharp-libvips-<platform>`.
3. Extract into a staging dir as a standard `node_modules` layout.
4. In-binary `Bun.build` (`target: 'bun'`, `format: 'cjs'`, externals for the
   never-installed optional ids: `@img/sharp-libvips-dev*`, `@img/sharp-wasm32*`)
   → single self-contained `dist/index.js` (all JS deps inlined; sharp's
   native-load loop stays dynamic).
5. Place natives where sharp's FIRST candidate (`../src/build/Release/
   sharp-<platform>.node`, relative to the bundle) finds them, and the libvips
   lib dir where the `.node`'s rpath/RUNPATH expects it.
6. **Verify:** load the staged bundle and run a real probe resize in-process.
   This is the tripwire for sharp changing candidate paths on future bumps.
7. Atomic rename staging → `~/.bakin/media/sharp/<version>/`; write install
   receipt (version, shas, platform). Old version dirs removed after commit.

**Load** (`packages/core/src/media/sharp-loader.ts`, stays THE one loader):
1. `import('sharp')` — works in dev tree / npm installs (devDependency).
2. On failure: import `<store>/dist/index.js` when the receipt exists.
3. Both fail → null as today, but error surfaces now name the fix.
   A cached null is re-probed when a store receipt appears (in-process doctor
   repair must not require a server restart).

`scripts/build-binary.ts` adds `sharp` to the compile externals (playwright
#837 posture): binary import failure becomes deterministic, ~213 KB dead JS
dropped.

## Components

1. **Shared downloader** — `packages/core/src/net/download-verify.ts` (name
   final at implementation): fetch with timeout → sha256 vs pin → optional
   tar extract (arg-injection-hardened) → caller verify hook → atomic rename.
   Refit `src/core/agent-packages/bin-installer.ts` and
   `requirements-installer.ts` onto it (behavior-preserving, own commit).
2. **Pin** — `packages/core/src/media/pin.ts`: sharp version + per-platform
   tarball URLs/shas. Regenerated by `scripts/generate-media-pin.ts` (reads
   npm registry metadata, computes shas). Pin-bump runbook in the knowledge doc.
3. **Installer** — `packages/core/src/media/installer.ts` (or src/core/media/):
   check/install pair per the onboarding contract.
4. **Onboarding component `media`** — thin wrapper; wire into
   `COMPONENT_ORDER` (15 → 16), bump `ONBOARDING_VERSION` 3 → 4, CLI
   check/install allowlists, `FIXABLE` whitelist in request-handler.
5. **Doctor** — `media.sharp` system check (`plugins/health/lib/system-checks/
   media.ts`) + repair action; ok in dev tree, action_required on
   binary-without-store, warn on unsupported platform.
6. **Error surfaces** — `downscale.ts` and `asset-mutations.ts` sharp-missing
   messages name the remediation (`bakin install media` / Health repair).
7. **Docs** — new `.claude/knowledge/media-pipeline.md`; update
   `binary-size.md` sharp row, CLAUDE.md (data-dir tree, onboarding count,
   install/check lists, Key Patterns line), doctor/knowledge inventories,
   user-facing install docs if they enumerate components.

## Testing Strategy

- **Compile-and-run regression (#886 pattern):** fixture compiles a tiny
  entry with `--compile`, stages the store **from the repo's own
  node_modules** (no network), runs install-phase bundling + load-phase
  resize inside the produced binary. On linux CI this covers the linux
  RUNPATH placement the darwin spike couldn't. Teeth variant: without the
  store, bundled import must fail (pins the premise; if it starts passing,
  bun learned to embed sharp and the machinery is obsolete).
- **Downloader unit tests:** loopback HTTP server, tiny fake tarballs —
  timeout, sha mismatch refusal, tar extraction, verify-hook failure, atomic
  commit, idempotent fast path. Refit commits keep bin-installer/
  requirements-installer suites green untouched (behavior-preserving proof).
- **Onboarding:** exact-order pin updated (16 components); component
  check/install unit tests with mocked installer.
- **Doctor:** check states (ok dev-tree / missing / unsupported), repair plan+apply.
- All tests mock BOTH content-dir resolvers; no `~/.bakin` writes ever.

## Boundaries

- **Always:** verify-then-commit before any rename into the store; honest
  unsupported-platform reporting; `bun run lint` + `typecheck` + full suite
  before push; behavior-preserving refits as isolated commits.
- **Ask first:** changing the sharp version pin; touching the antfly
  installer (out of scope — follow-up issue); any release-pipeline change.
- **Never:** network calls from request paths (no lazy self-heal); parallel
  loader or second image engine; sharp in the SDK declaration graph; test
  writes to real `~/.bakin`/`~/.openclaw`.

## Success Criteria

1. Fresh binary install (onboarding run) → >2 MB image enrichment succeeds
   with no user action. Verified live on 3737 before merge.
2. Existing degraded install → `media.sharp` action_required incident with
   working one-click repair; enrichment succeeds after repair WITHOUT server
   restart.
3. Compile-and-run test green on darwin (local) and linux (CI).
4. `bin-installer` + `requirements-installer` share the ONE downloader; their
   existing test suites pass unchanged.
5. Dev tree behavior unchanged (bundled sharp import, no store needed).
6. Docs: media-pipeline knowledge doc exists; binary-size.md sharp row,
   CLAUDE.md deltas landed; follow-up issue filed for antfly refit.
7. `bun run lint`, `bun run typecheck`, `bun run test` all green.
