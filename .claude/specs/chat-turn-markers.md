# Turn-Completion Markers & Honest Interrupted-Turn Sweep — Spec

**Issue:** #735. The boot sweep (`sweepInterruptedTurns`) stamps the honest interrupted row only when a transcript ENDS on a user row. A turn dying mid-stream AFTER partial assistant/tool rows persisted (the common crash shape for long replies — the engine persists incrementally) gets NO marker: the reply silently truncates, and the queue's boot auto-drain (#729) then appends fresh content directly beneath the dishonest gap.

Single-user box; no back-compat shims; tech-debt-lean. **Four-silo plan review applied 2026-07-26** (over-complication / tech-debt / UX-honesty / test-strategy); amendments below are marked (S1–S4).

## Design (decisions grounded in code, 2026-07-26)

| # | Decision | Choice + rationale |
|---|---|---|
| D1 | Terminal marker | New transcript row kind **`done`** (`{kind:'done', ts, turnId}`), persisted by the ENGINE at clean success settle only — abort and error turns already end with their own terminal rows (`aborted`/`error`). Invariant after this change: **every settled turn ends with a terminal row** (`done | aborted | error`). Bonus honesty win (S2/S3): an empty-reply completed turn (runtime done, zero agent rows) currently leaves the tail on the user row and is FALSELY stamped by today's rule 1 — the done row fixes that existing false positive. |
| D2 | Opt-in per consumer | Engine config gains **`terminalMarkerRows?: boolean`** (renamed from `completionRows` — "completion" reads LLM-completions-adjacent; this name states the contract, S3); **chat is the only opt-in**. Grounded: brands' brainstorm store is a BOUNDED 300-row array (markers would evict ~20-25% of real rows), bits consumers own unknown zod schemas that would reject an unannounced kind, and none of them run transcript sweeps. |
| D3 | Era gate: summary field first, transcript scan as legacy fallback | `ChatSummary` gains **`markerEra: boolean` (zod default `false`)**; `createChat` writes `true`. Sweep gate = `summary.markerEra || rows.some(kind==='done')`. The original ≥1-done-row scan alone was a PERMANENT hole: every chat ever created starts with zero done rows, so turn 1 of every future chat would stay unswept forever (S2). With the field, new chats are marker-era from turn 1; the transcript-scan branch covers pre-upgrade chats that complete a turn, and **sunsets** when the last pre-upgrade chat is deleted (doc note in M3). Accepted miss narrows to: pre-upgrade chats only, until their first completed turn — including the plural case where the first post-upgrade crash AND its re-drain crash both go unstamped (doc line, S1/S2). |
| D4 | Rendering | `done` rows are INVISIBLE: `foldConversation` skips them with an early `continue` BEFORE the agent-side builder/turnId-split block (a done row reaching the builder branch would open a phantom empty turn — today's latent bug for any unknown agent-side kind). No UI change; the sweep's stamped error row carries the interrupted `turnId` so it folds into the truncated turn. |
| D5 | Sweep stamps: last row only, two wordings | No trailing-run collection — the transcript's last row alone carries both the kind (terminal check) and the turnId (stamp target) (S1). Wording drops the asserted cause ("server restart" is when the stamp lands, not necessarily what killed the turn — kill -9/OOM/power loss, S3): rule 1 (ends-on-user) → **"Interrupted — the server stopped before the agent could reply."**; rule 2 (partial tail) → **"Interrupted — the server stopped before this reply finished."** |
| D6 | Retry scoping | `onRetry` renders only on the FINAL turn of the conversation (S3): retry always re-sends the newest user row, so a mid-transcript "Try again" (routine once stamped turns sit above drained queue content) would re-send the WRONG message. One-line condition where `Conversation` assigns `onRetry`. |
| D7 | Rejected alternative (recorded per S1) | A chat-local `openTurnId` field on ChatSummary (set at first agent-row append, cleared at completion) would solve most of #735 inside `plugins/chat/` with less surface. Rejected because: user rows carry NO turnId (verified), so it cannot fix the empty-reply false stamp D1 fixes; correctness would ride a distributed implicit state machine (kind-aware set/clear in append + an onTurnComplete hook whose failures the engine swallows → hook failure = false stamp); completion state would live outside the transcript (no self-description, lost to index damage); and the terminal-row invariant is kit-level groundwork in the ONE shared turn engine. The D3 fix already requires the same summary-field mechanism, erasing the alternative's main surface advantage. |

## Implementation surface

1. **Engine** (`src/core/conversation-turns.ts`): `ConversationTurnRow` union gains `{kind:'done'; ts; turnId?}`; config gains `terminalMarkerRows?: boolean` (doc: "chat-style sweepable transcripts only — bounded/foreign stores must not opt in"); `runTurn`'s clean-success path (NOT the aborted branch at the same site — `aborted` is that path's terminal) persists the done row AFTER `recorder.finish()` rows, BEFORE `onTurnComplete` (derived-state hooks see a fully-terminal transcript). SDK type mirror additive + **mutual-assignability parity pin** (the #737 `chunk-taxonomy-parity` pattern) — forgetting the mirror strands external consumers (S2).
2. **Kit** (`src/components/conversation/fold.ts`): `ConversationMessage` union gains the row; early-continue skip per D4. `conversation.tsx`: `onRetry` only on the final turn (D6).
3. **Chat** (`plugins/chat/`): `TranscriptRowSchema` + `ChatTranscriptRow` + client `TranscriptRowDto` gain the kind (forgetting the zod member = every read drops the row and logs "malformed" forever — pinned by a one-way engine-row→chat-schema parse test, S2); `ChatSummarySchema` gains `markerEra` (default false), `createChat` writes true; stream-bridge sets `terminalMarkerRows: true`; `appendTranscriptRow` bumps NOTHING for done rows (no messageCount/preview/unread — tool-row class); **sweep v2**:
   - skip chats with an in-flight turn (predicate injected from the bridge — the void-fired activation sweep races live sends, S3);
   - last row `user` → stamp turnId-less, "before the agent could reply" (any era);
   - else if marker-era (D3 gate) AND last row kind ∉ {done, aborted, error} AND last row has a turnId → stamp `{kind:'error', turnId, message: 'Interrupted — the server stopped before this reply finished.'}`;
   - turnId-less non-user tails and legacy transcripts → untouched (a completed legacy turn is NEVER falsely marked);
   - boot ordering unchanged: sweep → `restoreQueues` (stamps land above drained rows).
4. **Search**: unaffected — `chatSearchBody` allowlists user+assistant kinds (verified).

## Testing strategy (S4 — full hole list applied)

- **Engine** (`tests/core/conversation-turns.test.ts`): done row on success w/ flag (carries turnId, lands LAST); **settle-shape matrix** — with the flag on, EVERY settle shape (clean success, error-chunk, thrown-mid-iteration, abort-during-stream, **abort thrown in a drained turn's async prefix**, drained combined turn) leaves a terminal last row and never a done row on abort/error (structurally pins the invariant against future settle branches, S2/S4-H1); flag absent → no row ever; extend the existing hook-order test: `…row:assistant → row:done → complete → event:done` (S4-H4); drained combined turns get exactly one marker (flag-enabled queue-harness variant).
- **Fold** (`tests/sdk/conversation-fold.test.ts`): one test, three fixtures — done mid-transcript (skip precedes turnId-flush logic), trailing (turn folds `complete`), `[user, done]` (no phantom agent turn) (S4).
- **Sweep** — NEW `tests/plugins/chat/sweep.test.ts`, pure fs fixtures, zero timing (S4): (a) marker-era ends-on-user → turnId-less stamp, rule-1 wording; (b) marker-era partial tail → stamped with tail turnId, rule-2 wording; (c) tails ending done/aborted/error → untouched; (d) legacy truncated-looking tail + legacy turnId-less-error tail → untouched; (e) **idempotency, both stamp shapes, sweep run twice** → exactly one stamp (S4-H2); (f) empty transcript / fresh chat → untouched, no throw (S4-H5); (g) broken chat (missing transcript file) doesn't stop the sweep — the next chat still gets stamped (S4-H6); (h) marker-era turnId-less tail → untouched (S4-H7); (i) crash-mid-drain shape `[…, done, user, user, assistant(t)]` → stamped with the drain turnId, rule 1 does NOT fire (S4-H8); (j) in-flight chat skipped.
- **Chat store/stream** (`tests/plugins/chat/store.test.ts`, `stream.test.ts`): appendTranscriptRow(done) bumps nothing; GET serves done rows (route-level — NO page-render RTL pin, deleted as duplicate flake surface, S4); stream happy-path transcript ends `done` with the turn's turnId (the ONLY test proving the bridge flag is wired — existing exact-shape row assertions gain the trailing done); abort/error stream tests assert no done row.
- **Parity pins**: engine↔SDK mutual assignability; engine `ConversationTurnRow` → chat `TranscriptRowSchema.parse` one-way (S2).
- **Queue boot test** (`tests/plugins/chat/queue.test.ts`): extend for stamp-above-drained-rows ordering (marker era).

## Boundaries

- **Never:** falsely mark a completed turn (era gate + terminal-set check are load-bearing); emit marker rows to consumers that didn't opt in; render done rows; infer completion from row-kind heuristics when a marker exists; stamp a turnId-less non-user tail.
- **Out of scope:** brands/bits sweep upgrades (they keep ends-on-user); retroactive marker backfill; ledger-based in-flight tracking (issue's option 2 — heavier, unneeded).
